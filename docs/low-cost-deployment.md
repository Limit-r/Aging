# 低成本部署分析与量化路线（决策记录）

> 时间：2026-08-24 ｜ 本文件记录**现场低成本部署**的选型结论与分析过程，作为后续
> "模型量化部署 / QAT" 工作的前置决策基线。技术路线为**先 PTQ 量化启用，后续再上 QAT**。

---

## 一、现场部署需求（已确认约束）

- 54 路摄像头 + 9 个 ESP32 电流检测 → 3 台设备（每台 18 摄像头 + 3 ESP）→ 千兆交换机 → **低配 PC 集中算力**。
- **必须全程 54 路同时静默检测**（负载恒定），交互式"点看"叠加在个别路上。
- 检测帧率需求宽松：每路只需 **4~15 fps** 即可捕获 LED 闪烁（闪烁统计基于 off→on 翻转）。
- 当前算力现状：推理全链路 **PyTorch**（`ml/vision/engine.py` 的 `DetectionEngine`，`device` 自动 cuda/cpu）；GUI 进程不 import torch，检测全在 `ml/vision/worker.py` 子进程。

## 二、算力量化结论

- 静默监控 54 路 @320×320 ≈ **216 帧/s** YOLO。
- GPU 上实测 8GB 卡：**显存峰值仅 ~1.2GB**、约 920 帧/s 计算天花板 → 余量 4 倍。
- 交互式与 monitor 并发时由 `_infer_lock` 串行化前向，显存安全。

## 三、降配方案（可插显卡 → 采用方案 B）

| 方案 | 结论 |
|------|------|
| A. 核显 + OpenVINO | 可行但改动中；核显性能波动 |
| **B. 低端入门独显（复用 PyTorch CUDA）** | **采用。** `DetectionEngine` 按 `cuda` 自动 device，换 NVIDIA 卡基本零改动 |
| C. 纯 CPU + OpenVINO INT8 | 54 路吃力，CPU 被占满 |
| D. 算力分散到 3 台盒子 | 部署拓扑重构，成本高 |

### 选型（NVIDIA 优先，避免改动）
- **RTX 3050 6GB**（Ampere sm_86，CUDA 12.8 直接支持，自带 NVDEC 硬解）→ 首选
- 二手 RTX 3060 12GB / RTX 2060 / P4（前确认驱动支持 CUDA 12.8）
- 避开 Intel Arc 作首选（需走 ONNX+OpenVINO，改动变大）

### 主机配置底线
- 主板：可插 PCIe x16 独显
- GPU：RTX 3050 6GB 级（带 NVDEC）
- CPU：8 核/8 线程以上（54 路并发 NMS+读帧）
- 内存：≥16GB；硬盘：SSD 512GB+；网络：接千兆交换机

### 两个"真坑"（GPU 不是唯一瓶颈）
1. **54 路读帧/解码压 CPU**：OpenCV/FFMPEG 默认软解 H.264，务必让解码走 NVDEC 硬解。
2. **CPU 核心数**：monitor 并行 NMS 用 12 线程 + 读帧 + 系统开销。

## 四、量化部署路线（本文件的核心推进方向）

> 目标：在低配 NVIDIA 卡上以 INT8 提升吞吐 / 降低功耗，同时保住 LED 小目标召回。

1. **阶段一（当前）——PTQ 量化部署**：对训练好的 FP32 模型做**训练后量化**，
   先在 RTX 5060 Ti 上验证精度与收益，生成可部署的量化模型（ONNX INT8 QDQ /
   TensorRT / torch INT8 视工具链定）。
2. **阶段二——QAT 量化感知训练**：精度不满足时，用**量化感知训练**在原生管线中
   微调，以更小精度损失换取 INT8 部署。
3. 部署侧：NVIDIA 卡建议 **ONNX + TensorRT INT8**（Q/DQ 节点，精度最高），需要校准集。

> 备注：PTQ 与 QAT 的具体工具链、校准集来源、精度验收指标见后续量化专项文档；
> 本文档只做决策与需求基线。
