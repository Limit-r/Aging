# 现场安全防御部署 Checklist（老化检测系统）

> 适用范围：老化检测现场（54 路摄像头 + 9 个 ESP32 电流检测 → 低配 PC 集中算力）。
> 目的：默认"设备与网络已被攻破"，做纵深防御，让单点失守无法横向放大。
> 调用号：本文件为全局安全基线，按层勾选执行，改动硬件/网络/固件前先复核本清单。
> 说明：所有"用户可见中文"如需写入系统界面，仍走 `labels.*` + `narrative.event()` 约定。

---

## 一、威胁核心认知

**真正要防的不是"破解 WiFi 密码"，而是以下顺序**（按风险从高到低）：

| 优先级 | 威胁 | 一句话说明 |
|--------|------|-----------|
| P0 | 摄像头默认后门/固件漏洞 | 低端摄像头带云服务、P2P 穿透、UPnP、弱默认口令，攻破它即撕开内网 |
| P0 | ESP32 固件被篡改/注入 | 电流检测节点被刷恶意固件，可跳板横向、污染参数 |
| P1 | 内网横向渗透 | 设备同网段互信，攻破任一台即可横向打 PC/其他摄像头 |
| P1 | 物理实体篡改 | 现场无人时插拔设备、读 flash、替换伪装设备 |
| P2 | WiFi 无线嗅探/伪造 | 空口不保密，配置正确后可降为次要风险 |
| P3 | 社会工程 / 供应链 | 最"真"的入侵往往来自固件、云 SDK 后门 |
| P2 | 办公网与摄像头网混用 | 办公网失守 = 摄像头网失守（若互通） |

**总原则：不寄希望于守住某一个口，而是每层都挡一次。**

## 二、资产与信任边界

```
[ 摄像头1..54 ] --WiFi(5GHz)--> [ AP x3 ] --有线千兆--> [ 交换机 ] --> [ PC 双网卡 ]
[  ESP32 x9  ] --WiFi(5GHz)--> [ AP x3 ]                        ^
                                            [ 摄像头网卡 | 办公网卡:无路由 ]
```

- 信任边界 1：互联网 ↔ WiFi（无线入网，P2）
- 信任边界 2：WiFi 客户端 ↔ 内网有线（P0，横向扩散点）
- 信任边界 3：摄像头/ESP ↔ PC（数据面，P0，核心）
- 信任边界 4：办公网 ↔ 摄像头网（P2，最好完全隔离）

## 三、设备层加固

### 摄像头（54 台）
- [ ] 关闭云服务、账号解绑云平台
- [ ] 关闭 P2P 穿透 / 手机远程
- [ ] 关闭 UPnP / 自动端口映射
- [ ] 关闭路由器/交换机上的外网端口映射（不做 DMZ、不做端口转发）
- [ ] RTSP 或 ONVIF：强凭据（≥16 位随机，字母+数字+符号）
- [ ] 修改默认 HTTP/onvif 口令，禁用默认 admin
- [ ] 登录/播放走后端，不暴露公网
- [ ] 锁固件：能找到则开启"固件完整性/签名校验"或禁止远程升级
- [ ] 摄像头 IP 固定 + 记录每个 MAC（建立资产台账）
- [ ] 只向 PC 的固定 IP 开放拉流，其余访问拒绝

### ESP32 电流检测（9 个）
- [ ] 启用 **Secure Boot**（固件签名，防刷恶意固件）
- [ ] 启用 **Flash 加密**（防读 flash 提取密钥/固件备份）
- [ ] 通信用 **`WiFiClientSecure`**（TLS 1.2/1.3），可选 **mTLS 双向证书**（PC 与 ESP 互验）
- [ ] 只用 **主动长连接**上报（ESP 连 PC，不开放监听端口）
- [ ] 业务关闭：HTTP / Telnet / OTA（不用的服务全关）
- [ ] 密钥/证书存加密分区，不烧明文
- [ ] 上报异常（重连、无心跳、证书失效）并入合法性事件报警

### 密钥与凭据管理
- [ ] WiFi 密码、RTSP 凭据、证书、ESP 密钥不在明文代码/配置里
- [ ] 统一密钥库，轮换机制（至少半年/泄露即换）

## 四、网络层加固

### AP（3 台，AP 模式）
- [ ] 改为 **AP 模式**（避免双重 NAT）
- [ ] 独立 SSID（3 台各不同名），单独加密
- [ ] **WPA3-SAE**（防离线字典破解；WPA2 的 PMKID 可被脚本离线破）
- [ ] 关多频合一（2.4G/5G 分开命名）
- [ ] 5GHz 错开信道（用手动锁 80MHz：Ch36 / Ch100 / Ch149）
- [ ] 关 WPS、关 UPnP、关远程无线管理
- [ ] 无线 MAC 白名单 + 开 WPA3 时同步启用 SAE
- [ ] AP 位置直视覆盖，信号稳定

### 交换机与分段
- [ ] 千兆交换机（有线回传）
- [ ] 摄像头 / ESP / PC 分 **VLAN** 或独立网段
- [ ] 交换机 ACL：VLAN 间默认拒绝，仅放行必要流向（摄像头→PC：“拉流”，ESP→PC：“上报”）
- [ ] 摄像头之间如需隔离用 ACL；默认互信要关闭
- [ ] 静态 IP + ARP 绑定/MAC 白名单，拒绝陌生设备取址

---

## 五、主机层加固（PC，低配主机）

### 双网卡硬隔离（关键项）
- [ ] 摄像头网卡与办公网卡**分别独立网卡**，且**无路由互通**
- [ ] 防火墙按 Windows profile（Private vs Public）隔离两台网卡
- [ ] 办公网被入侵不触及摄像头网，反之亦然
- [ ] 网卡间禁用网络桥接、禁用 Internet Connection Sharing

### 服务与端口
- [ ] 只开放必要入站端口（ESP 上报入口、摄像头拉流、推理入口）
- [ ] 摄像头侧网卡防火墙：默认拒绝入站，仅放行对 ESP 长连接应答、对摄像头拉流出站
- [ ] 关闭不必要服务（远程桌面仅内网+强口令、禁用 Guest）
- [ ] 最小化账户，密码策略强口令

## 六、数据 / 流程 / 物理层

- [ ] 部署/重建数据前先确认（沿用项目习惯）
- [ ] 固件/资产台账：型号、固件版本、MAC、IP（变更审计基线）
- [ ] 合法性监控并入现有报警：非授权设备接入、摄像头周期断连重连、异常流量
- [ ] 机箱上锁、网口标记、定期巡检
- [ ] 备用固件/配置留存，可快速回滚

---

## 七、落地优先级（按性价比）排序

1. **PC 双网卡 + VLAN/IPC 隔离**（一次配置，堵住横向扩散与互串）
2. **摄像头硬加固**（关云/P2P/UPnP + 强凭据 + 锁固件 + MAC 白名单）
3. **ESP32：mTLS 长连接 + Secure Boot + Flash 加密**（可跑通的可复用例程优先落地）
4. AP 加固 + WPA3 + 5GHz 信道调优
5. 合法性事件接入现有报警体系
6. 物理防护与资产台账

## 八、与现有系统的集成点

- 检测链路全在 `ml/vision/worker.py` 子进程，GUI 不 import torch——
  安全事件判断可复用现有叙事/报警通道（`narrative.event()`）。
- 摄像头"断连/重连/丢帧"异常天然可作为安全事件的候选信号。
- 后续做 ESP32 mTLS 上报示例时，PC 端校验逻辑与现有检测引擎同机部署。
