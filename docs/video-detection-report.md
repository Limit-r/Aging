# 视频检测 · 报告存储与查看（设计）

> 文档版本：v1  ·  2026-08-25  ·  待审阅
> 状态：需求已确认，进入方案定稿（仅设计，未开发）

---

## 0. 目标

把视频检测/静默监控的结果从"进程内内存、会话结束即丢"升级为**可长期留档、可在数据中心图形化回看**。

- 每路设备（54 路摄像头 + 对应 54 路电流）保留完整的**逐秒状态灯**记录与**电流**记录。
- 单次会话**最长 4 小时**（可能更短），磁盘上**至少保留半年**。
- 数据中心"历史/趋势/导出"页签从占位 → 可**图形化查看报告**。

---

## 1. 范围与决策（已与用户确认）

| 决策项 | 结论 |
|--------|------|
| 记录数据 | **54 路摄像头 LED 状态灯 + 54 路电流**（复用现有 `ChannelReading`，每 cell 4 电流） |
| 电流采样率 | **保持 2s/条**（沿用 DemoDataSource 现状，不强制对齐到 1Hz） |
| LED 状态采样率 | **保证每秒 1 条**（逐秒 H/L） |
| 落盘归属 | **worker 侧写 LED 状态 + GUI 侧写电流，按会话关联**（见 §3） |
| 文件粒度 | **一次启动记录一个文件，且针对单个设备记录**——不按天汇总（见 §4） |
| 电流空态 | 无老化设备检测时电流回传 **0 或为空**，报告须区分"空/无数据"与真实 0（见 §3） |
| 保留策略 | **磁盘配额 50GB**，至少容下半年的会话量，满载从最旧文件回滚（见 §5、§6） |
| 存储格式 | **紧凑二进制** |
| 报告范围 | 54 路摄像头 + 54 路电流 两类数据合并呈现 |
| 报告入口 | 数据中心"历史 / 趋势 / 导出"页签（现占位） |

## 2. 数据流总览（跨两个进程）

```
        ┌─────────────── GUI 进程 ───────────────┐
        │ ChannelReading(4 电流/2s)  ──→ 电流 recorder ──→ 电流日志 .bin │
        │   (DataSource → on_reading)              ▲                   │
        └──────────────────────────────────────────┼────────────────────┘
                                                    │ 会话 ID
        ┌─────────────── worker 进程 ──────────────┼──────────────────┐
        │ 54 路视频 → 检测 → last_states(1Hz) ──→ LED recorder ──→ LED 日志 .bin │
        └──────────────────────────────────────────┴──────────────────┘
                                                            │ 读取合并
                    ┌────────── 数据中心 · 报告 ────────────▼──────────┐
                    │ 会话列表 → 热力图(LED/电流) → 单路方波+I-t → 导出 │
                    └──────────────────────────────────────────────────┘
```

- **LED 状态**：由 worker 内独立 1Hz 采样器落盘（不依赖 GUI `snapshot` 轮询，防丢帧）。
- **电流**：`ChannelReading` 本就只存在于 GUI 进程（`DemoDataSource` 推到 `on_reading`），故**在 GUI 侧落盘**，不必跨进程发回 worker。
- 两路日志用一个**会话 ID**（时间戳 + 序号）关联，报告期按墙钟时间轴合并。
- **文件按单设备、单启动**：每台设备（CH-XX）每次启动单独一个文件（见 §4），不把 54 路/一天揉进一个文件。

> 注：这修正了"全部 worker 侧落盘"的直觉 —— 因为电流源头在 GUI 侧，跨进程回传只会增加复杂度与丢帧风险，拆两条各自落盘、按会话合并最贴合现有依赖方向。文件再按单设备/单启动细分，便于单机离线查看、原子归档与该设备的单独保留。又：因无老化设备时电流回 0/空，报告渲染对"空/无数据"与真实 0 **必须区分**（否则会出现大面积"假 0 电流"误导）。

## 3. 数据模型（统一墙钟时间轴）

```
LED 记录 (1 Hz, 每行 = 1 秒):
    墙钟时间戳(4B) | 位图(本设备 ≤8 灯 = 1B)   // 仅本设备

电流记录 (2 s, 每行 = 1 采样):
    墙钟时间戳(4B) | 4 × float32(16B)     // 仅本设备；无设备时为 0/空

- **只存逐秒/逐采样原始值**。闪烁次数、单次闪烁时长、电流曲线、异常统计等指标**不落盘**，报告期从原始值重推导（自洽，改算法不迁历史数据，避免两套口径不一致）。
- 两种采样率并存（LED 1Hz / 电流 0.5Hz）：报告时各按自身分辨率渲染，用墙钟匹配；LED 热力图秒级、电流 I-t 曲线 2s 点。
- **电流空/0 语义**：某采样无老化设备时回传 0 或空。落盘需带"有效/无效"标记（或用 NaN 表示空），报告渲染把**无效段**置灰/跳过，不画成真实 0。

## 4. 二进制文件布局（每设备 · 每次启动一个 .bin）

一个文件 = **一台设备的一次启动**，不按天/不按 54 路汇总。

```
┌ 文件头: magic 「VDRP」 | 版本 | 会话 ID | 设备 CH-XX | 启动墙钟 |
│         led 采样率=1Hz | 电流采样率=0.5Hz │
├ 段 A（LED）  : 定长行 { ts:int32, bitmap:1B }          // 本设备 ≤8 灯
├ 段 B（电流） : 定长行 { ts:int32, valid:u8, currents:4×float32 }
└ 文件尾: 结束墙钟 | 行数 | led 数（便于随机定位/截段）
```

- 电流段 `valid` 标志：0 = 无设备（0/空），1 = 有效读数，供报告区分空/真实 0。
- 定长行 → 任意秒可随机定位；行数 → 断点续读/截段统计。
- 目录：`ml/detection_logs/<设备 CH-XX>/<启动开始时间戳>.bin`
  - 例：`ml/detection_logs/CH-12/20260825_143000.bin`
- **LED 段与电流段合在同一文件**（原子归档/删除、单设备单独保留）；该设备本次启动无电流来源时，段 B 置空（仅 LED）。
- 文件数量级：54 设备 × 半年会话数；单文件极小（见 §6），靠文件头 + 目录按设备/时间索引。

## 5. 保留策略（至少半年，配额 50GB）

- 写侧周期扫描 `ml/detection_logs/` 总大小，**超配额按文件时间从最旧删除**（按文件粒度，不逐条删，开销低）。
- 配额默认 **50GB**（可配），覆盖半年峰用量（见 §6）。
- 删除以"设备目录下最旧文件"为优先，保证任何单设备也保留到配额允许的最大历史。

## 6. 磁盘用量估算（配额依据）

单文件 = 单设备单启动(最长 4h)：

| 数据（单设备 · 4h） | 量 |
|---|---|
| LED 状态（14400s × ~5B） | ≈ 0.07 MB |
| 电流（7200 行 × ~21B） | ≈ 0.15 MB |
| **单设备单启动文件** | **≈ 0.22 MB** |

54 设备 × 单会话(4h) ≈ **12 MB/整批**；半年：
- 每天监控 8h（2 会话）→ 360 会话 → **≈ 4.3 GB**。
- 全天连续 → **≈ 15 GB**。

→ **配额 50GB** 足以覆盖"半年全天连续 + 约 3 倍余量"；已知每天只跑 8h 可降到 10GB 以下。

## 7. 报告视图（数据中心"历史/趋势/导出"页）

- **设备 · 启动列表**：按"设备 CH-XX → 该设备的历次启动"两级浏览全部落盘文件（含不足 4h 的短启动），显示时间区间/时长。
- **全局热力图**：X=时间（最多 4h）、Y=通道；可**切换 LED 闪烁视图 / 电流视图**（两类数据统一呈现的核心视图；电流无有效段处置灰/跳过）。
- **单设备详情**：LED 方波图（复用 `VsResultPanel` 样式）+ **电流 I-t 曲线叠加** + 闪烁计数/单次闪烁时长统计。
- **聚合导出**：闪烁排行、异常通道高亮；CSV 导出逐秒状态、PNG 导出报告图。

---

## 8. 分阶段交付

- **阶段 1 · recorder**：双录（worker 侧 LED 1Hz + GUI 侧电流 2s）+ 阈值回滚。可独立验证落盘与容量。
- **阶段 2 · 报告读取与渲染**：会话列表、全局热力图、单路 LED+I-t 详情。
- **阶段 3 · 聚合与导出**：排行/异常高亮、CSV/PNG 导出。
